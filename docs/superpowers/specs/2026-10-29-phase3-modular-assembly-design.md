# Phase 3 模块化组合系统设计

## 意图

在 Phase 2 的独立厅堂、直廊和基础构件之上，增加可定位、可连接、可拆分、可替换的建筑模块组合内核。建筑仍由本地 Python 规则生成；组合系统保留各模块边界和身份，不把编辑对象过早压平成一整块方块模型。

## 目标

- 定义 `Module`、`ConnectionAnchor`、`ClearanceZone`、`Connection` 和 `Assembly` 数据结构。
- 支持模块平移、绕 Y 轴旋转四分之一圈、沿 X/Z 镜像；坐标、锚点、预留空间和方向性方块状态一起变换。
- 按锚点位置、相反朝向、连接类型和开口宽高对齐连接模块；不静默修正连接高差。
- 支持移除连接、按连接图拆分组合、替换单个模块，并确定性地渲染为 `VoxelModel`。
- 检测实体方块重叠、锚点错位/朝向/开口不匹配、连接高差及檐口预留空间冲突。
- 用厅堂与直廊等独立生成结果组成一个两进院落示例，并验证替换一个模块不会修改其他模块。

## 非目标

- 不实现工程 JSON 的模块持久化、历史版本、撤销或局部依赖重算（Phase 4）。
- 不实现 AI、图形拖拽、城镇规划、Minecraft 世界写入或 Blender 渲染。
- 不把自动连接等同于真实古建营造考证；连接规则是显式、可测试的方块几何约束。
- 不做自动碰撞修复；验证器报告问题，由调用者调整模块或连接。

## 设计决策

模块是带固定 `module_id` 的独立 `VoxelModel`，坐标采用当前模型坐标，不另设隐式原点。锚点保存整数位置、朝向、连接类别和开口尺寸；锚点可以落在模块占地边界之外，表示连接平面。檐口等净空以带类别的半开区间 `BoundingBox` 表示。

变换函数返回新的模块，不原地修改输入。旋转复用现有 `rotate_model_y`；镜像增加对应的坐标及方块状态变换，`left/right`、朝向连接属性及 16 向 `rotation` 同步翻转。连接时只旋转和平移待加入模块，保持其锚点高度；若高度不同则拒绝连接并指出高差。

`Assembly` 保存按 ID 索引的模块和连接记录。连接要求锚点类型、宽高兼容，且朝向相反；替换保留原 ID 和连接记录，验证器负责报告替换后失效的锚点。按连接图拆分时，每个连通分量形成独立组合。渲染顺序按模块 ID 排序；实体方块重叠不依赖覆盖顺序解决，导出前应通过验证。

## 验收

- 变换后方块、锚点、净空边界和方向/左右状态一致；输入模块保持不变。
- 连接后的两个锚点位置重合、朝向相反，宽高和连接类别兼容；高度差会被拒绝或报告。
- 验证器能指出方块冲突、门洞尺寸/锚点错位、檐口净空冲突。
- 断开边后，拆分结果与连接图的连通分量一致；替换模块保留其他模块的对象与方块数据。
- 由多栋独立厅堂和直廊组成的两进院落可渲染并稳定重复生成；`.schem` 回读方块数与边界一致。

## 范围裁定

Phase 3 使用可执行的几何锚点与净空约束，不从 Litematic 或参考图自动推断连接规则。模块工厂/示例显式声明门洞、连廊端点和檐口净空，避免把未经验证的语义猜测包装成自动检测能力。
