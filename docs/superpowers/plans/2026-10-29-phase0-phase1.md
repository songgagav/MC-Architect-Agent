# Phase 0 and Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish an installable, tested Python project and a deterministic block model that writes and reads Sponge Schematic v3.

**Architecture:** Keep block IDs and state properties in a small core model, store sparse block coordinates in `VoxelModel`, and serialize the bounded volume through an NBT-backed Sponge v3 adapter. A project JSON layer and CLI form the first usable workflow.

**Tech Stack:** Python 3.12, pytest, nbtlib, GitHub Actions, Sponge Schematic Specification v3.

**Spec:** `docs/roadmap.md` and the user-provided nine-phase plan in the current conversation.

## Global Constraints

- Target Minecraft Java 1.21.5 with DataVersion 4325.
- Use the official Sponge Schematic v3 NBT schema and `x + z * Width + y * Width * Length` indexing.
- Preserve complete block state properties during serialization and rotation.
- Never write generated content into an existing Minecraft save.
- Do not commit or push automatically.

## Review Focus

- Reject dimensions outside the Sponge v3 unsigned-short limits.
- Preserve property-bearing states such as stairs, slabs, doors, and fences.
- Serialize palette IDs as VarInts in the specification's X/Z/Y storage order.
- Read offsets and nonzero origin coordinates without shifting block content silently.
- Keep project JSON load/save deterministic and preserve unknown module fields.
